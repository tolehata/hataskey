# ナビバーに統合した「引っ張って更新」モック

`index.html` をブラウザで開く。外部通信・依存インストール・サーバー起動は不要。

- 左は Hataskey UI の丸いナビ、右は Hataskey UI S の角型ナビ。
- 各タイムラインの先頭で、ノート本文のあたりを下へドラッグ／スワイプする。
- ナビの上端を固定し、下端が抵抗感を持って伸びる。タブ全体が薄れ、同じ面の中央に案内文が現れる。
- 120px未満で離すと更新せずに戻る。120px以上では「離して更新」となり、離すと更新を模擬する。
- 戻りは減衰するばね。案内文の退場とタブの復帰を伸縮に連動させる。文字やアイコン自体は縦に変形させない。
- 更新後は架空のノートが先頭に1件入る。実際のAPI、アカウント、設定には書き込まない。

## 確認用操作

「演出を再生」「短く引っ張る」でそれぞれ更新／キャンセルを再生できる。「進行度」で途中の見た目を止めて確認し、「離す」で元に戻す。進行度はキーボードでも操作可能。

スマホ／PC幅、ライト／ダーク、動きの軽減を切り替えられる。OSの動きの軽減設定も尊重する。画面サイズ・動きの設定変更とタブ非表示時には途中の演出をリセットする。

確認する動作：両UIの伸縮／途中キャンセル／閾値後に引き戻す／連続再生／スクロール途中では発動しない／横方向の操作では発動しない／複数タッチでキャンセル／更新中の二重実行防止。

## 通知と重なったとき

「通知の重なりを試す」で新着、操作通知、時報、投票、RSSを発生させられる。「引っ張り中に通知を発生」をオンにして再生すると、引っ張り中と更新開始後の両方に新着が届く。

- 引っ張り・復帰・更新中は更新案内が優先。通常ナビの内容と高さは一旦保持し、裏側への受信で形が跳ねないようにする。
- 復帰後は、期限内の投票 → 最新の操作通知／時報 → 新着ノート → RSSの順に1種類を表示。
- 新着は件数を加算して保持。更新開始時点までの件数を消化し、その後に届いた分は残す。
- 操作通知の表示時間は隠れている間停止。古い操作通知を次々と遅れて再生しないよう最新の1件に置き換える。
- 投票期限は隠れている間も進む。期限切れの投票を後から再表示しない。
- 通知の有無で変わるナビ高さは、引っ張りの終了後に滑らかに調整する。

これは競合時の表示方針を確認するモックであり、RSS本文・投票処理・本番通知キューは接続していない。
