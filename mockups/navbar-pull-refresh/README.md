# 引っ張って更新：UI / UI S 比較モック

`index.html` を開き、各タイムラインの先頭でノートを下へ引っ張る。初期表示はモバイル幅。画面、テーマ、動きの軽減を上部で切り替えられる。外部通信や依存の追加は不要。

UI S のモバイル表示は、上部タブを置かず、RSS／操作通知／新着のバナーと独立した投票表示をタイムラインの上に置く。下部は投稿フォームとメニュー・検索・ホーム・通知・Hatask・ウィジェットをまとめたカプセル。タイムライン先頭から下へ、または下部カプセルのナビ行から上へスワイプすると、同じ更新演出が始まる。ガラスのカプセル全体が最大40px伸びて少し持ち上がり、投稿フォームとナビが一緒に薄れ、中央に回転矢印と案内が現れる。投稿フォームのDOMと自然な高さは保ち、文字は拡大縮小しない。上部のバナーと投票表示も動かない。ホーム長押しでタイムライン選択の見本を開ける。PC表示の上部タブと UI 側のナビは残している。

「演出を再生」は120pxの更新閾値を越える操作、「短く引っ張る」はキャンセルを再生する。「進行度」で途中の伸びを止め、「離す」で復帰を確認できる。タイムラインを下へ引く操作は先頭でのみ、ドックを上へ引く操作はナビ行でのみ始まる。上方向の案内は「引き上げてリロード」。横方向・逆方向では発動せず、pointercancel や複数タッチではキャンセルする。ドックの通常タップとホーム長押しは短い移動では維持する。更新中の案内はカプセルが元の高さに戻っても完了まで残り、完了時に投稿フォームとナビが戻る。動きの軽減時は跳ね返りと矢印の回転を抑える。

「通知の重なりを試す」から RSS、新着、操作通知、投票を切り替えられる。各通知と更新案内の帯は共通の角丸で、通知の色と文字の余白を保つ。「引っ張り中に通知を発生」をオンにすると受信競合を再生する。引っ張り中は表示中の面と高さを保ち、UI S モバイル以外では背景が伸びた領域まで続く。復帰後に受信分を反映し、更新開始後の新着は残す。操作通知の表示時間は隠れている間停止し、投票期限は進む。UI S モバイルでは投票とバナーを同時に表示できる。更新後のノート追加は架空の表示で、本番のRSS本文・投票処理・通知キューには接続していない。
