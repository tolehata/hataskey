# 本実装へ進める際の設計メモ

本体実装の仕様と確認状況は[packages/backend/test/LTL_PUNCH.md](../../packages/backend/test/LTL_PUNCH.md)を参照。この文書はモック時点の設計メモとして残す。

このモックはブラウザー内だけの試作。本番の投稿、共有HP、オンライン人数、実績保存には接続していない。

## 確定した体験

- 本文に同じ拳が3つ以上連続する投稿で発動。`🤛🤛🤛`、`👊👊👊`、`🤜🤜🤜` が対象。`🤛👊🤜` は対象外。
- 巨大な拳をクリック／タップして撃退。上部ナビに人数に応じたHPを表示。
- 開始時はナビ内に「上から何か来る...??」を表示し、外周を赤いグラデーションの緩やかな点滅で強調。HP表示を0から満タンへ滑らかに充填し、満タンから約2秒後に拳が降り始める。準備中の先制攻撃は受け付けない。
- 降下中はTLの表示要素が少しずつ崩れる。
- 拳は下向き・従来モックの約4倍で、上端の外から侵入する。風圧や破片を伴い、先端の進行に合わせてノートが画面下へ崩落する。
- 襲来中はノートのボタン・リンク・キーボード操作を無効化し、拳以外へのタップの通過を遮断する。勝敗直後も短時間保護して連打の誤爆を防ぐ。
- 成功時は表示をすぐ復元し、上部ナビに「撃退に成功！」。
- 成功で拳が消える際は、大小多数の拳が画面全体へ飛び散る。表示専用レイヤーは操作を遮らず、終了・再試行で片付ける。動きを控える設定では静止した少数の拳へ置き換える。
- 失敗時は「撃退に失敗...」を表示し、TLが崩れる演出を5秒間付与。その後に復元する。
- 成功の実績：**パンチは消えた...**／説明：そもそも何この手は？
- 失敗の実績：**TLはパンチされた...**／説明：パンチがあるゲームだったね...

## 既存コードとの接続候補

| 目的 | 既存の参照箇所 | 本実装時に必要な扱い |
| --- | --- | --- |
| 投稿からの発動 | `packages/backend/src/core/TimelineCollapseService.ts`、`NoteCreateService.ts` | 投稿保存後のサーバー処理で判定。現行のTL崩れるはローカルユーザー・public・チャンネル外のノートを対象にする。LTL掲載対象としてこの条件を出発点にし、古いノートの再読込や受信再送で発火させない。 |
| 上部ナビと演出 | `packages/frontend/src/ui/simple.vue`、`components/hataskey3/Hk3App.vue` | LTL表示時のみに接続。ナビのメッセージ・HPは破壊演出の対象から外す。 |
| 崩れる動き | `packages/frontend/src/utility/hata-timeline-collapse-effect.ts` | 現行の10秒演出をそのまま呼ばず、今回の失敗状態は5秒にする。途中終了・画面移動でアニメーションを破棄し、元の表示へ復元。 |
| 人数 | `packages/backend/src/server/api/endpoints/get-online-users-count.ts` | 現行APIは直近10分のlastActiveDateを持つユーザー行を数え、応答を60秒キャッシュする。LTLの現在の閲覧人数ではない。 |

## 共有対戦に必要な処理

サーバーで1つのイベントID、開始時刻、締切、最大HP、現在HP、状態、更新番号を管理する。発動の重複防止とHP更新・終了判定は原子的に行い、クライアントからHP値や勝敗結果を受け取って信用しない。攻撃は認証ユーザーに紐付け、連打の上限や複数タブからの二重処理を制御する。途中参加・再接続は最新状態を取得し、更新番号で古いイベントを無視する。

準備の充填表示は実際のHPへの攻撃・回復とは区別し、共有イベントの開始時刻に同期させる。満タン後の待機中も攻撃を拒否し、降下開始時刻を過ぎてから受け付ける。充填時間はモックで1.2秒として調整し、待機は2秒とする。途中参加で全員に新しい準備時間を与え直さない。

人数を「LTLを開いているローカルユーザー」とするなら、現行APIの流用だけでは足りない。LTL参加状態の期限付き記録をユーザーIDで一意に数え、同じ人の複数タブでHPを増やさない。モックの人数スライダーは、この集計方針を確定するものではない。人数の更新間隔と、残HP割合を維持する仮の調整方式は実運用の遊びやすさを見て決める。

投稿イベントにはクールダウンと同時発動の上限を設ける。発動用の文字列を再投稿しても進行中のイベントを置き換えない。崩壊は描画だけに限定し、ノート・リアクション・フォーム入力などの実データを変更しない。

ノート操作の保護は表示オーバーレイだけに依存させない。ノート領域の`inert`、操作要素の無効化、イベント処理側のガードを組み合わせ、既に押し始めたポインターや勝利直後のクリックが下のボタンへ抜けないようにする。ゲーム終了後は元の有効／無効状態とフォーカスを復元し、ナビや演出を閉じる操作は使えるままにする。

実績はサーバーの確定した終了状態から一度だけ付与する。攻撃参加者に限るか、LTLの観戦者にも付与するかは本実装前に決める。モックの獲得表示は参加資格や本番保存の仕様を確定するものではない。演出を閉じたこと・再読み込み・リセットは失敗として扱わない。

動きを控える設定では落下や大きな回転を抑え、HP・勝敗・実績は確認できるようにする。本番の共有戦ではバックグラウンドのタブでもサーバー上の時間は進むため、復帰時に再同期する（モックは体験確認のため非表示中の時計を停止）。
