# LTL パンチ・インタラクションモック

`index.html` をブラウザで開いて操作します（file://、サーバー・依存追加不要）。実際の投稿、API、実ユーザー、実データには接続していません。架空の投稿と人数を用いる、無音のローカルモックです。ブラウザによる目視確認は未実施です。

- 初期状態は通常のLTL。既定文の「モック投稿」で拳が出現します。
- 同じ 🤛 / 👊 / 🤜 を3つ以上続けると発動。前後文章、皮膚色、variation selectorは許容。混在、2連続、空白区切りは対象外（発動条件は確定仕様）。LTL以外はengineで対象外。
- 巨大な拳のボタンをクリック・タップ、またはフォーカスしてEnter / Spaceで攻撃（8 HP）。1.2秒でHP表示を充填し、満タンのまま2秒待機した後に36秒かけて降下。HPゼロで撃退、時間切れで通過。成功時は直ちに拳が消え、TLを復元し、上部ナビに「撃退に成功！」を表示。失敗時は上部ナビに「撃退に失敗...」を表示し、5秒間のTL崩壊演出の後に復元します。再投稿で再開できます。
- HP最大値は `80 + 20 × オンライン人数`（1〜40）。途中の人数変更では残HP割合を維持。
- 「みんなの攻撃を再現」は架空の仲間による自動攻撃。共有同期はしていません。
- 成功実績「パンチは消えた...」（そもそも何この手は？）、失敗実績「TLはパンチされた...」（パンチがあるゲームだったね...）をセッション内だけ表示。同じ実績の重複獲得通知なし。本番実績は未追加。結果プレビューボタンは疑似結果を同じ終了処理で表示します。リセットでは実績を獲得しません。
- 「演出を閉じる / リセット」でいつでも終了。「動きを控える」とOSのreduced-motion設定に対応。ページ非表示中はゲーム時計を停止。

`engine.js` は副作用のない状態処理を `globalThis.HataPunchEngine` / Nodeの `module.exports` で公開します。時間単位は秒です。

- `trigger(text, scope = 'local')`: 発動判定（boolean）
- `create(people = 8)`: 待機状態を作成
- `start(state)`: 充填状態へ（進行中は上書きしない）
- `setPeople(state, people)`: 人数・最大HPを更新
- `attack(state, damage = 8)`: HPを減らし、ゼロならwon
- `tick(state, delta)`: 充填・待機・降下時間を進める
- `maxHP(people)`: 最大HPを算出

状態は `phase`（idle / charging / warning / falling / won / escaped）、`people`, `hp`, `maxHP`, `elapsed`, `progress`。各更新は新しい状態を返します。

本番接続に向けた検討は [INTEGRATION.md](INTEGRATION.md)、権利の確認は [RIGHTS.md](RIGHTS.md) を参照。新規ソースはリポジトリの既存ライセンスに従います。

## 降下・崩壊演出の改訂

拳を下向きに回転し、約4倍（デスクトップ720px / 狭い画面600px）の文字サイズに変更。警告中はTL上端の外に配置し、先端が上から下まで降下します。風圧線・衝撃波・砂塵が降下中に自動で発生し、同時粒子数を制限します。

ノートの元の位置を基準に揺れ・部品の剥離・カードの落下を段階的に実行。失敗時は上から連鎖して落下し、5秒後に復元します。成功・リセットは即復元。襲来中と失敗演出中は返信・リアクションを無効化し、透明な操作保護面でクリックを遮断。成功・リセット直後も380ms保護を維持します。

通常時の返信ボタンはモック案内、リアクションボタンは架空の件数を切り替えます。動きを控える設定は初期状態でOSに従い、チェックを手動変更するとその選択を優先します。OS設定自体は変更しません。

`geometry.js` の `HataPunchGeometry` / Node exportsは純粋関数です：`position(stageHeight, glyphSize, progress, phase, reduced)` は `tip/top/size`、`damage(noteTop, noteHeight, tip)` は段階0〜3、`rubble(noteTop, stageHeight, index)` は最終落下位置 `x/y/angle` を返します。

この改訂についてブラウザ操作・目視確認は未実施です。先の検証記録は初版の履歴であり、改訂後の見た目を検証済みとするものではありません。

改訂後の機械検査は13項目が成功（Node v24.19.0、終了コード0）。画面高320〜560pxと拳600／720pxの組合せで、上端外の開始位置・警告から降下への連続性・単調な進行・下端到達を確認。簡易DOM上で、自動エフェクト、実測位置に基づく崩壊段階、通常時のリアクション、襲来中のinert／disabled、380msの終了保護、失敗時の瓦礫維持と5秒後の復元、実績重複防止、粒子上限30と掃除、OS設定からの手動切り替え、600pxへの切り替え、HTML参照整合を確認した。

実ブラウザーの描画・当たり判定を検証するものではない。開いているページを再読み込みし、「動きを控える」がオンの場合はオフにすると、改訂した降下・崩壊演出を確認できる。

## Twemojiと撃退時の爆散

巨大な拳・挿入ボタン・撃退時に飛散する拳は、ローカルのTwemoji SVGを使用します。入力欄と説明のUnicode文字は通常のテキストです。素材のクレジットとライセンスは [ATTRIBUTION.md](assets/twemoji/ATTRIBUTION.md) を参照してください。

撃退成功時はTLのクリップ領域外を含む画面全体に、デスクトップ96個／狭い画面64個の拳が放射状に飛び散ります。24〜72px、2.25〜2.7秒でフェードし、2.76秒後に全ノードを削除。動きを控える場合は10個の静止表示と850msの穏やかなフェードになります。失敗時にはこの演出は出しません。

爆散は独立した上限付きのfixedレイヤーで描画し、クリックやフォーカスを取得しません。新規試合・結果プレビュー・リセット・動き設定の変更で、前のアニメーションとタイマーをキャンセルし、全粒子を削除します。今回の改訂もブラウザによる目視確認は未実施です。

## 上部ナビの襲来準備（今回の改訂）

上部ナビに「上から何か来る...??」と赤・オレンジ・深紅のグラデーション外枠を表示。1.2秒の穏やかな点滅と、0〜100%へ滑らかに充填するHP表示で襲来を予告します。満タンから2秒後に拳を表示し、降下を開始します。準備中の拳は非表示・無効で、攻撃も状態処理で拒否します。HPは実値を維持し、充填表示だけを変更します。数値・ゲージ・読み上げ用の値は一致します。

時間定数はengineの `DURATIONS`（charging:1.2 / warning:2 / falling:36）と `PREPARATION` / `TOTAL` に集約。`displayedHP(state)` が充填中のsmoothstep表示HPを返します。拳の導入は降下開始から約0.9秒で先端がTL内に入り、そのまま下端まで進行。上部ナビの領域を予約し、準備・降下・結果の表示をフェードで切り替えます。動きを控える場合は点滅・動く切替を止めますが、準備時間とHP表示の意味は維持します。
