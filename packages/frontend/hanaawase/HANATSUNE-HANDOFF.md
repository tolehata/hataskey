## 5. 踏みやすい地雷(詳細は SPEC §0.4 / §0.45 / §0.46)

**必ず §0.45 と §0.46 を読むこと。** ここは要約であって代替ではない。
特に危険な3つ:

1. **Git Bash の `grep` は日本語の文字クラスを静かに壊す**(§0.45-1)
   → エラーが出ないまま**誤った数字**が返る。設計側はこれで誤った前提を仕様に書いた。
   日本語の検索・カウントは PowerShell の `[regex]::Matches()` を使う。
   ⚠️**日本語検索でゼロ/極端に少ない結果が返ったら、結論を出す前にまず道具を疑う**

2. **生成した長い日本語は必ず汚れる**(§0.45-4,5 / §0.46-型7)
   → 英語・スペイン語・ハングルの混入、完全な重複、設定にない属性の追加。
   **P7 の `story.ts` 移植が最も危険**。移したら元Markdownと**文字数・行数を突合**し、
   混入検査と重複検査を**機械でかけてから**完成とする

3. **変更したのに依存先を直さない**(§0.46-型2。★最頻出)
   → 識別子・スキーマ・アセット名・固有名詞を変えたら、**その語で全文検索して波及先を潰す**。
   仕様に書いた**理由**も、前提が変われば壊れる

その他(頻出): UNC パスでは Bash の `mkdir`/`cp` が失敗する→**PowerShell で作って一覧確認**(§0.45-3)。
PowerShell の `Set-Content`/`Out-File` は文字化け/BOM→`UTF8Encoding($false)` で書く(§0.45-2)。
CSS Modules の動的キーは解決されない→`v-if` 静的参照か `data-*`(§0.4-1)。
否定形だけの指示は暴走する→禁止を書いたら**望ましい代替を同じ場所に**書く(§0.46-型5、画像生成で最も効く)。

- **文体**: 「!」の乱用・ひらがなポップ・急かす文言が混じっていない

**フェーズ個別の受け入れ基準は SPEC §13 の表が正本**。代表例:
- P0: 表情6種×2人+立ち絵+背景8枚が §12.2 のパスに揃う(1枚ごとにWORKLOG更新)
- P0.5: 15pxで潰れない/ライト・ダーク両方で視認/ゲーム内に `ti ti-*` が残っていない
- P1: 全テスト green。`Math.random` 不使用。自動シャッフルと打ち水が**同一関数**

  (⚠️前回の index を流用して「開催中」を続けない)。⚠️判定は `start <= now && now < end`、
  `end` は**終了日の翌日 0:00**。⚠️プレイ中は判定しない。⚠️画面文言は「**開催時間**」に統一
