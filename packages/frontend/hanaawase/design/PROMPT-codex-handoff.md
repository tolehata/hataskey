## 0. ⚠️この環境の地雷（ここを外すと「やったつもり」になる）

### 0.1 検証は必ず WSL 側の docker

Windows側の docker CLI から `-v "/home/stili/...:/w"` でマウントすると⚠️**リポジトリではない別物**（中身が `packages` 1件だけ）を掴みます。`node_modules` が無いのでツールが起動せず、⚠️**grep が空なのを「エラー0」と読み違えます**（実際に2回発生）。

```
wsl.exe -d Ubuntu -e bash -lc 'cd /home/stili/dev/cherrypick-hata && docker run --rm -v "$PWD:/w" -w /w/packages/frontend node:22-slim sh -c "node node_modules/vitest/vitest.mjs run src/pages/hanaawase/"'
```
- ⚠️`node:22-alpine` は musl で rollup のネイティブbinaryが読めない。**`node:22-slim`**
- vue-tsc は `NODE_OPTIONS=--max-old-space-size=10240` が要る

### 0.2 ⚠️`| tail` を通すと終了コードが化ける
`docker compose build 2>&1 | tail -25` の終了コードは **tail のもの**です。⚠️**ビルド失敗を「成功」と誤読しました。** 必ず `cmd > /tmp/x.log 2>&1; echo "exit=$?"` の形で取ること。

### 0.3 ⚠️テストは `.vue` を通らない
`vitest` は `.test.ts` しか読まないので、⚠️**`index.vue` の import 漏れは捕まりません**（実際に `watch` の import 漏れを踏み、vue-tsc で見つけました）。⚠️`.vue` を触ったら**必ず vue-tsc**。

### 0.4 ⚠️陽性対照は「集計ループより前」に仕込む
後ろに足すと検査対象に入らず**空振り**します（実際に一度やりました）。⚠️「新規どうしの一致」の対照を**完全同一**で作ると、⚠️**完全重複の検査に先に吸われて10文字一致が発火しません**。⚠️**別の文で10文字だけ重ねる**こと。

### 0.5 ⚠️実機は「ビルドしないと1文字も変わらない」
コンテナの `/cherrypick` はイメージ内のコピーで、バインドマウントではありません。⚠️**症状の報告を受けたら、まず配信物に修正が入っているか grep で確かめること。**

```
docker exec cherrypick-hata-web-1 sh -c 'grep -rl "探す文字列" /cherrypick/built | wc -l'
```

### 0.6 ⚠️ビルドのヒープ（対処済み・戻さないこと）
`vite build` が `Reached heap limit` で落ちていました。⚠️**RAM不足ではなく**、`.wslconfig` が意図的に `memory=6GB`＋`swap=16GB`（「山は swap へ逃がす」と明記）なのに、⚠️V8 が既定の上限を小さく決めて swap を使う前に自分で落ちていたのが原因です。
→ `Dockerfile` の native-builder 段に `ENV NODE_OPTIONS=--max-old-space-size=8192` を1行追加済み。⚠️**外さないこと。**
