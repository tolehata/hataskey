# 花常 アイコン体系（Tabler からの脱却）

## 0. 方針：⚠️「押すもの」はSVG、「持つもの・眺めるもの」はラスター

Tabler（`ti ti-*`）は本ゲーム内では使わない。独自意匠に置き換える。
ただし**技法を2つに分ける**。基準は見た目の好みではなく、**そのものが何であるか**。

| | 対象 | 技法 | 理由 |
|---|---|---|---|
| **押すもの** | 操作・ナビ・状態表示・**道具ボタン**（鋏/手直し/打ち水）・★の花 | **SVG**（§1〜§3） | 状態や テーマで**色が変わる**／15pxで潰れない必要がある／押すたびに見るので軽さが要る |
| **持つもの・眺めるもの** | **イベントアイテム・飾り・報酬・花手帖に飾る品** | **ラスター**（§5） | 色が変わらない／大きく表示される／**物語が乗る**ので質感が要る |

⚠️**この線引きを間違えないこと。**
「鋏」は物語に関わる（F-17 祖母の鋏）が、**盤面で押すボタン**なのでSVG。
「きよばあの湯呑」は押さない。**貰って眺める物**なのでラスター。

### 押すものをSVGにする理由（技術的な理由）
1. ⚠️**同一アイコンが実行時に色を変える。** design `04-event.dc.html:277` で、星表示が
   `var(--accent)`（獲得）と `var(--line)`（未獲得）を出し分けている。
   さらにライト/ダークのテーマ切替がある。**焼き込んだラスターでは不可能**で、
   「アイコン種 × 状態色 × テーマ」の全組合せを作ることになり**枚数が爆発する**
2. **生成枠を消費しない。** 画像生成はテキストの3〜5倍速で枠を減らす（SPEC §12.15）。
   30種以上のアイコンを生成すると枠を大きく削り、しかも**意図と違う絵が出る事故**が起きる
3. **画風が完全に揃う。** `design/flowers.js` が既にこの画風（viewBox 64×64・墨2px輪郭・
   フラット塗り＋影1段）を手続き的に描いている。**同じ生成器で描けば揺れない**
4. **小サイズで鮮明。** 実際の描画は 15〜38px。ラスターは @2x/@3x が要るがSVGは不要
5. **画像ファイルが1枚も増えない**（TSモジュール1本に収まる）

⚠️この5点は**押すもの**についての話であり、**§5 の物語アイテムには当てはまらない**
（色が変わらず、大きく出て、質感が要るため）。混同しないこと。

## 1. 画風規約

`design/flowers.js` の作法を継承する。⚠️2段構えにする。

| 段 | 用途 | 描き方 |
|---|---|---|
| **線画（stroke）** | 操作・ナビ・状態 | 墨の輪郭線のみ、中を塗らない。`stroke="currentColor"` `stroke-width="4"`（viewBox 64基準）、`stroke-linecap="round"` `stroke-linejoin="round"` |
| **面塗り（fill）** | 道具・アイテム・花 | `flowers.js` と同一。フラット塗り＋影1段＋墨 `#2b2620` の2px輪郭 |

- **viewBox は全て `0 0 64 64`**（`flowers.js` と統一）
- 線画は **`currentColor`** を使い、呼び出し側が `color:` で色を決める
  → テーマ切替・状態色に自動追従する
- 面塗りは CSS変数を SVG 内で参照（`fill="var(--accent)"` 等）
- ⚠️**細部を描き込まない。** 15pxで潰れる線は引かない。**要素は3〜5本まで**
- ⚠️**遠近法・グラデーション・影の多段を使わない**（`flowers.js` の影1段まで）

### 2.4 イベントアイテム・飾り
⚠️**SVGでは作らない。§5 のラスター（一枚絵）で作る。**

## 3. 実装

```
packages/frontend/src/pages/hanaawase/icons.ts
```
`flowers.js` と同じ形式で、**全アイコンを関数で生成して文字列SVGを返す**。

```ts
export const ICONS: Record<string, () => string> = {
  'kaeshi':   () => stroke(`M24 18 L40 32 L24 46`),          // 返し矢羽根
  'noki':     () => stroke(`M10 30 L32 14 L54 30 M18 30 ...`), // 店の軒
  'hasami':   () => filled([...]),                            // 和鋏
  // ...
};
```
- 線画は共通ヘルパ `stroke(d)` で `stroke="currentColor" stroke-width="4"` を付与
- 面塗りは `flowers.js` の `build()` をそのまま流用（⚠️同じ関数を使うことで画風が揃う）
- Vue側は `<span class="hicon" v-html="ICONS.hasami()">` 相当のラッパを1つ作る
- ⚠️**Tabler の `ti ti-*` を本ゲーム内で使わない**（本体の他画面では使い続けてよい）

### 移行の順序
1. まず **§2.2 のゲーム・道具**（画面の主役。ここが変わると印象が変わる）
2. **§2.1 の操作・ナビ**
3. **§2.3 のメタ**

⚠️移行途中で Tabler と混在してよい。**一度に全部やろうとしない**。
⚠️イベントアイテムはSVGではなく §5（ラスター）で作る。この順序には含まれない。

1. まず **§0 の表で「押すもの」か「眺めるもの」かを判定する**。
   ⚠️眺めるものなら `icons.ts` ではなく §5 のシートへ
2. 押すものなら `icons.ts` に関数を1つ足す
3. ⚠️**15px で潰れないか確認**（要素3〜5本まで）
4. ⚠️**既存アイコンと形が被っていないか確認**（特に丸物・四角物）
5. 線画か面塗りかを §1 の基準で選ぶ

## 5. 物語アイテムの絵（ラスター・スプライトシート）

対象: **イベントアイテム・飾り・報酬**——プレイヤーが**貰って、眺める物**。
⚠️UIアイコン（§2.1〜2.3）はここに含めない。

### 5.1 なぜこれだけラスターか
- **色が変わらない。** カードの上に置かれる「物の絵」であり、状態やテーマで塗り替わらない。
  §0 で挙げたSVGの決定的な利点（色の可変）が、ここでは**必要ない**
- **大きく出る。** 交換所のカードで 100px 前後、花手帖ではさらに大きい。SVGの平板さが目立つ
- **物語が乗る。** 「きよばあの湯呑」は道具ではなく**記憶の器**。3〜5要素の線画では軽すぎる

### 5.2 画風（⚠️既存と浮かせないための指示）
- **墨 `#2b2620` の輪郭線を残す**（`flowers.js` と同じ約束事）。⚠️これが無いと花のピースと馴染まない
- 塗りは**フラットを基調に、影と質感を1〜2段だけ**足す。⚠️写実的なレンダリングにしない
- パレットは基調6色＋イベント差し色。⚠️**原色・金属光沢・強いハイライトを使わない**
- **背景は透過**。⚠️影を落とすなら**接地影を薄く1枚**まで（浮いた投影を描かない）
- 構図は**真横〜やや俯瞰の静物**。⚠️手に持った絵・使用中の絵にしない（物そのものを見せる）
- ⚠️**文字を描かない**（地図の地名、帳面の文字など。読めない線で示す）

### 5.3 スプライトシート規約
⚠️**1品1ファイルにしない。1シートに格子で並べて一度に生成する。**
一度に生成すると**画風が自動的に揃う**——これがシートにする最大の理由（枚数削減は副次）。

- 格子は**等間隔の正方形**。⚠️生成時は**アスペクト比で指示**（3×3なら全体 `1:1`）。
  ピクセル指定は守られない（SPEC §12.15-1）
- 1マスの保存目安 256×256。マス間に余白を入れない
- ⚠️**1シートに入れるのは、同じイベント・同じ用途のものだけ。**
  混ぜると1品の失敗でシート全体を作り直すことになる
- 生成前に**マスの並び順と各マスの内容を文章で列挙する**（下記 5.4 の形式）
- ⚠️**生成後はマスごとに検品**。1マスでも違ったら**そのマスだけ単品で生成して差し替える**
  （シート全体を作り直さない。⚠️枠の無駄）
- 切り出し座標は TS の定数表に持つ：`{ id: [col, row] }` ＋ 1マスの寸法
